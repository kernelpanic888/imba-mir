# Паспорт сюжетных глав IMBA

**ID:** `IMBA-NARRATIVE-CHAPTERS-v1`  
**Статус:** `IMPLEMENTED / VERIFIED VERTICAL SLICE`  
**Обещание:** каждая глава является самостоятельной игровой дугой, а новая
глава добавляется как новый модуль контента без переписывания главного экрана.

## 1. Единица истории

Единицей расширения является `StoryChapterDefinition`. Глава ДОЛЖНА сама
объявлять:

- стабильный `id`, порядок, номер, название и статус;
- собственный текст и формулу главного меню;
- используемый игровой runtime и правило старта;
- собственное вступление и все его реплики/звуковые cues/фигуры;
- собственный финал, конфликт, следствие и действие выхода;
- ключ прогресса, по которому меню показывает продолжение.

Текст, изображения и пороги одной главы ЗАПРЕЩЕНО прошивать в универсальный
проигрыватель сцен. Экран читает выбранный модуль и не знает заранее, как
называются его герои или реплики.

## 2. Три честных входа

Для выбранной главы интерфейс ДОЛЖЕН давать три разных действия:

1. `ПРОДОЛЖИТЬ` — войти в уже существующее состояние без повтора вступления и
   без сброса Мира.
2. `НАЧАТЬ ГЛАВУ` — создать новый Мир для runtime главы и начать с её
   вступления.
3. `ВСТУПЛЕНИЕ` — отдельно пересмотреть вступление, не изменяя прохождение.

Завершение вступления записывается отдельным ключом
`chapterId + sceneId`. Просмотр одной главы не отмечает просмотренной другую.

## 3. Реестр без верхнего предела

Структура production-кода:

```text
ui/app/story/
├── types.ts                    # контракт главы, сцены и финала
├── registry.ts                 # упорядоченный реестр и fail-fast проверка
└── chapters/
    ├── chapter-zero.ts         # самостоятельное интерактивное обучение
    └── chapter-one.ts          # полностью самостоятельная глава I
```

Чтобы добавить сюжетную главу с уже существующим игровым runtime:

1. создать новый файл в `chapters/`;
2. экспортировать полный `StoryChapterDefinition`;
3. добавить один import и один элемент в `STORY_CHAPTERS`;
4. добавить ассеты главы;
5. пройти build, server-render test и живой маршрут
   `меню → вступление → игровой runtime → финал`.

Реестр не содержит числа максимальных глав, но содержит ТОЛЬКО опубликованный
автором материал. Полоса выбора прокручивается внутри меню и не увеличивает
размер игрового экрана. Интерфейсу запрещено процедурно выдумывать названия,
события или продолжение глав II+ за авторским рубежом.

## 4. Fail-fast инварианты

При сборке/загрузке реестр отклоняет:

- повторяющийся `chapter.id`;
- ссылку на отсутствующее вступление;
- повторяющийся `scene.id` внутри главы;
- сцену без реплик.
- главу без явного состояния `PUBLISHED`.

`selectedChapterId` хранится отдельно от состояния Lean-Мира. Сюжет не имеет
права пересчитывать урон, допустимость заклинания, реакцию или сертификат.

## 5. Глава 0: обучение через наблюдение

`chapter-00-initiation` является публикуемым вступлением и полноценной
самодостаточной главой. Она не завершается после фиксированного числа ходов или
шагов. Игрок должен собственными действиями наблюсти девять основных фактов:
ручной тик, сотворение заклинания, перебитие Природы, многоосевой бросок,
проекцию, сдачу в память Тени, первый контакт, ответ живого Мира и выбор
мета-протокола.

Шаги по дороге считаются без верхнего предела. `12` — первый сюжетный рубеж, а не
вместимость дороги. После освоения всех фактов глава 0 возвращает игрока к
списку опубликованных глав.

## 6. Реализованный вертикальный срез главы I

Глава I `chapter-01-curse-road` вынесена в отдельный модуль. В нём находятся:

- главное меню «Иди к Волшебнику»;
- сцена 00 «Чистое информационное поле» из четырёх реплик;
- Ворон, прежняя Тень, граница и четыре звуковые заглушки;
- финальный конфликт, вторая форма Ворона и портрет Волшебника;
- привязка к `WORLD_JOURNEY_V1`.

Подтверждено 15 августа 2026:

- production build — PASS;
- UI tests — 2/2 PASS;
- отдельный запуск вступления — PASS;
- полный проход четырёх реплик и вход в игровое поле — PASS;
- `НАЧАТЬ ГЛАВУ` сбрасывает число шагов до `0`, а рубеж остаётся `R12` — PASS;
- viewport `1280×720`, document `1280×720`, внешнего overflow нет.

## 7. Цель живого взаимодействия

Уничтожение Мира не является победой. Ноль жизни Мира означает разрушенное
равновесие и поражение. Ворон входит с Миром в контакт, Мир отвечает
компенсацией, а игровая цель — проводить необходимые изменения,
сохраняя живыми и Ворона, и Мир. Интерфейс показывает производный индекс:

```text
balance = max(0, min(playerLife%, worldLife%) - ½·|playerLife% - worldLife%|)
```

Этот индикатор объясняет состояние, но не пересчитывает Lean-авторитетные
жизни, урон или допустимость перехода.

## 8. Честная граница

Архитектура допускает неограниченное число модулей, но сейчас реализован один
боевой адаптер `WORLD_JOURNEY_V1`, обучающая глава 0 и одна содержательная
авторская глава I. Новая глава на
тех же правилах добавляется только контентом. Глава с новой механикой потребует
новый runtime-адаптер и его тесты; типизированный реестр не выдаёт ещё не
написанное игровое ядро за готовый контент.
